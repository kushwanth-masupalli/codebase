1) what is thread ?

a thread is the smallest unit of CPU execution within a process. a process can contain one or more multiple threads .

threads belonging to the same process share resources such as the code section , data section and head but each thread has it own program counter and CPU registers and stack .


2) process vs thread 

a process is an independet execution environment with its own address space and resources whereas a thred is an execruiont unit inside a process

3) why are threads faster than process ? 

threads are generally cheper because threads within the same process share the smae address space and many resources .creating a new thread doesn't require creating an entirey separeate addres like a new process does . context switching between threads of the smae process can also involve less work than switghinc between separate processess.


4) User level vs Kernel level threads 
User-level:

Threads are managed by the application/runtime, without the kernel directly managing each thread.

Kernel-level:

Threads are managed by the OS, so the kernel can schedule each thread independently on CPUs.


5) Multithreading models 

1) many to one   = many user threads map to one kernel therad
2) one to one = one user thread is mapped to one kernel thread
3) many to many = many users threds are mapped to many kernel threads.
